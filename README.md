# 📄 Сборка отчёта НИР по ГОСТ 7.32-2017

Streamlit-приложение для менеджеров лабораторий: собирает отчёт о научно-исследовательской работе из **нескольких файлов разных форматов** в единый DOCX по ГОСТ — со сквозной нумерацией разделов, рисунков, таблиц и **ссылок на источники**.

## ✨ Что умеет

- Принимает на вход одновременно: **Word (.docx)**, **LaTeX (.tex)**, **Markdown (.md / .txt)**, **Excel (.xlsx)**, **CSV** — каждый файл становится «частью» отчёта; части можно переупорядочивать, отключать, удалять.
- **Сквозная нумерация** работает поверх всех частей: разделы 1, 2, 3…; рисунки 1–N; таблицы 1–N; ссылки на источники [1], [2]… в порядке упоминания.
- **Менеджер источников**: один источник на строку (`ключ | оформление по ГОСТ Р 7.0.5`); ссылка в тексте `[@ключ]` (или `[@ключ1, ключ2]`). Автогенерируется раздел «Список использованных источников».
- Из LaTeX-файла дополнительно извлекаются `\bibitem` из `thebibliography` и автоматически попадают в общий список.
- Автогенерация титульного листа, реферата-заглушки, автособираемого оглавления, нижнего колонтитула с номерами страниц — всё по ГОСТ 7.32-2017.
- Вкладка «Проверка ГОСТ»: чеклист обязательных элементов, статистика, отображение неопределённых ключей.

## 🚀 Запуск

```bash
pip install -r requirements.txt
streamlit run app.py
```

## 🧱 Архитектура

```
app.py              # Streamlit UI (вкладки: части / источники / проверка)
elements.py         # единые типы DocElement + сквозная нумерация
parser.py           # парсер Markdown-разметки (legacy-обёртка)
docx_parser.py      # парсер DOCX
docx_builder.py     # рендер DOCX по ГОСТ + список источников
gost_styles.py      # константы оформления
bibliography.py     # модель Reference и сквозная нумерация ссылок
document.py         # модель Report: части + источники + merge()
importers/
    markdown_imp.py # Markdown → DocElement
    docx_imp.py     # DOCX     → DocElement
    latex_imp.py    # LaTeX    → DocElement
    xlsx_imp.py     # XLSX/CSV → DocElement
```

Любой импортёр возвращает `ImportResult(elements, images, references, warnings)`. Модель `Report.merge()` склеивает части, проставляет сквозные номера, заменяет `[@key]` на `[N]` и собирает финальный список источников.

## 📝 Markdown-разметка

| Элемент | Синтаксис |
|---|---|
| Раздел (H1) | `# 1 НАЗВАНИЕ РАЗДЕЛА` |
| Подраздел (H2) | `## 1.1 Название подраздела` |
| Пункт (H3) | `### 1.1.1 Название пункта` |
| Рисунок | `[рисунок: имя.png \| Подпись]` |
| Таблица | `[таблица]` … `[/таблица \| Название]` |
| Маркированный список | `- пункт` |
| Нумерованный список | `1) пункт` |
| Ссылка на источник | `[@ключ]` или `[@a, b]` |
| Разрыв страницы | `---` |

## 📚 Источники

Формат блока во вкладке **«Источники»**:

```
ivanov2020 | Иванов И. И. Методы машинного обучения. — М.: Наука, 2020. — 320 с.
petrov2021 | Петров П. П. Классификация текстов на основе SVM // Вестник ВУЗа. — 2021. — № 4. — С. 12–25.
# строки, начинающиеся с #, считаются комментариями
```

В тексте ставите `[@ivanov2020]` — на выходе получите `[1]`, плюс готовый раздел «СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ» в порядке первого упоминания.

## 🤝 LaTeX

Поддерживается «обычный» LaTeX без кастомных пакетов:
`\section / \subsection / \subsubsection / \paragraph`, `itemize / enumerate / description`, `figure + \includegraphics + \caption`, `table + tabular + \caption`, `\cite{key}`, `thebibliography + \bibitem`. Сложные среды (`multicolumn`, кастомные команды) парсятся «как могут» — что не распозналось, попадает текстом.

## 📏 Параметры оформления (ГОСТ 7.32-2017)

- Поля: **30 / 10 / 20 / 20 мм** (лево / право / верх / низ)
- Шрифт: **Times New Roman 14 pt**, межстрочный **полуторный**, отступ абзаца **1,25 см**, выравнивание **по ширине**
- Заголовки: H1 — 14 pt, **жирный**, ПРОПИСНЫЕ, с новой страницы; H2 — 14 pt, жирный; H3 — 14 pt, *жирный курсив*
- Колонтитул: номер страницы по центру, 12 pt
- Список источников: **в порядке упоминания**, оформление каждой записи — по ГОСТ Р 7.0.5-2008
